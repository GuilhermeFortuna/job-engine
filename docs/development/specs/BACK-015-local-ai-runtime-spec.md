# BACK-015: Shared local-AI runtime, profile extraction, and readiness

**Status:** Draft  
**Product direction:** [`../../local-first-product-direction.md`](../../local-first-product-direction.md)  
**Depends on:** BACK-014  
**Implementation plan:** [`../plans/BACK-015-local-ai-runtime-plan.md`](../plans/BACK-015-local-ai-runtime-plan.md)

## Purpose

Make a bounded loopback model a first-class local capability for profile
extraction and grounded application answers while deterministic policy remains
authoritative. The model assists; it never selects jobs, controls the browser,
uploads files, authorizes submission, or invents personal facts.

## Requirements

### Runtime and model contract

- Ollama's loopback OpenAI-compatible endpoint is the initial supported runtime.
  The shipped default model is `qwen3:4b`; endpoint and model remain configurable.
- One backend-owned client and inference broker serve all callers. A configurable
  semaphore, default `1`, prevents browser workers from loading independent model
  copies or overwhelming 6 GB VRAM.
- Local requests have explicit context, output, timeout, queue, and concurrency
  limits. Local operation has no artificial dollar cap. Existing cloud-provider
  privacy and cost gates remain separate and fail closed.
- Every task uses a versioned JSON schema. Invalid JSON, schema mismatch,
  timeout, unavailable runtime, or unsupported model yields a typed failure and
  never becomes confirmed profile data or an auto-submittable answer.

### Profile extraction

- Deterministic PDF/DOCX text extraction runs first. The local model may propose
  structured identity, employment, education, skills, languages,
  certifications, and links from that text.
- Proposals retain source spans or deterministic text references and remain
  unconfirmed suggestions. The user must accept, edit, or decline them before
  they become confirmed profile facts.
- Work authorization, sponsorship, legal attestations, consent, demographic
  answers, compensation, relocation, and travel are never inferred from a
  resume or generated by the model.

### Application answers

- Existing deterministic profile and reusable-answer rules execute before model
  generation. Model claims must reference allowed confirmed profile or job
  evidence and pass the existing server-side policy validation.
- Model confidence is diagnostic only. It cannot grant full-auto eligibility or
  override frozen batch authorization, sensitive-answer rules, or exception
  handling.
- The broker supports application-answer and resume-extraction task classes; job
  suggestions and ranking are explicitly deferred.

### Readiness

- `GET /api/v1/local-ai/status` reports configured endpoint class, model name,
  reachability, model availability, last self-test result/time, schema revision,
  and sanitized failure code. It exposes no prompt, resume text, secret, or raw
  provider response.
- `POST /api/v1/local-ai/self-test` performs one bounded structured response test
  and persists only sanitized diagnostics.
- Local-AI unavailability produces `Ready with exceptions` when deterministic
  automation prerequisites are otherwise met; it is not falsely reported as
  fully ready and does not prevent ordinary search/profile editing.

## Constraints and non-goals

- The backend owns prompting, schemas, grounding, and inference scheduling.
  Electron and React never call Ollama directly.
- No model download is initiated without an explicit user action. The product may
  show the exact `ollama pull qwen3:4b` prerequisite, but does not silently
  install software or models.
- OCR, autonomous job choice, ungrounded cover letters, browser planning, and
  employer-facing AI disclosure policy are outside this Spec.

## Acceptance criteria

1. The default model can pass the structured self-test through a loopback
   OpenAI-compatible runtime within configured limits on the target local setup.
2. Concurrent callers share one broker and respect the configured inference
   limit, timeout, and bounded queue.
3. Resume proposals cite extracted source evidence and cannot silently confirm
   facts or populate prohibited sensitive fields.
4. Deterministic answers retain precedence; malformed, ungrounded, unavailable,
   or timed-out model results become specific review exceptions.
5. Status and failure responses contain no private source text, prompts, paths,
   credentials, or raw model payloads.
